从其他编程智能体应用迁移过来

本页内容
  1. 有哪些变化
  2. 哪些保持不变
  3. 第一步
  4. 开始使用

如果你已经在用另一个应用并行运行编程智能体，Gitoodo 最主要的改变是：你不再需要亲自启动每个会话。你的议题就是队列，一旦某个议题就绪，Gitoodo 就会启动一个工作进程。本页展示哪些会变、哪些保持不变，以及如何先用一个仓库试一试。

有哪些变化#

  • 用议题取代你手动启动的会话。 你在代码托管平台上或在 Gitoodo 中写议题，或者在对话中描述一个计划，让 Gitoodo 起草议题。每个就绪的议题都有自己的工作进程、worktree 和分支。
  • 问题会主动来找你。 需要做决定的工作进程会在它的议题中提问。你在问我的中的一张卡片上回答，而不必盯着终端等提示出现。
  • 拉取请求就是成果。 每个工作进程最后都会产出一个拉取请求，Gitoodo 会在你的仓库要求的检查通过后，以你的仓库允许的方式合并它。
  • 状态保存在代码托管平台上。 标签、评论和拉取请求记录了发生的一切。Gitoodo 根据它们重建自己的视图；即使你不再使用它，工作及其历史也仍保存在代码托管平台上。

哪些保持不变#

  • 你的智能体命令行工具及其登录。 工作进程运行你电脑上安装的 Claude Code、Codex 或 Gemini CLI，用你的账户登录，使用你的订阅。Gitoodo 不需要 API 密钥。工作进程的权限和沙盒设置按会话生效，不会写入智能体自己的配置。
  • 你的检出目录。 在你的副本中，Gitoodo 只会拉取，并在它自己的文件夹中添加它自己的 gitoodo/… 分支和 worktree。它绝不会检出、重置或清理你的工作树，也绝不会动你的分支、stash 或其他工具创建的 worktree。
  • 你的代码托管平台和你的规则。 分支保护、必需的检查和评审依然说了算；Gitoodo 会等待它们。
  • 你仍然可以随时介入。 每个工作进程都是一个会话，你可以打开它、接管它、向它发送指令、暂停或取消它。

第一步#

  1. 下载 Gitoodo，安装后在引导中选择编排器。
  2. 连接你的代码托管平台，只开启一个仓库。对于已打开的议题，选择只处理新议题，这样旧议题不会自行启动。
  3. 让设置检查你的分支规则并安装后台服务。确保该仓库有一个 CI 任务；参见安全的自动合并。
  4. 在仓库视图中用新任务创建一个小的测试任务，或者给一个现有议题打上 ready 标签。
  5. 在仓库下面以会话的形式观察工作进程，在问我的中回答它的问题，再看看它创建的拉取请求。

这些都正常运行后，再开启更多仓库并提高工作进程数量；参见并行运行多个编程智能体。
