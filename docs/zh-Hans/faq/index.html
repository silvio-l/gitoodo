最常被问到的问题的简短回答。应用里遇到问题时，请先看故障排除。

Gitoodo 支持哪些代码托管平台？#

Forgejo、Gitea、GitHub 和 GitLab，也包括自托管的实例，两种模式都支持。你可以同时连接不同平台上的多个账户。

使用智能体需要 API 密钥吗？#

不需要。工作进程和编排器对话运行的是你已经在用的智能体命令行工具（Claude Code、Codex 或 Gemini CLI），使用你自己的订阅。Gitoodo 只检查该命令行工具是否已安装并已登录，从不索要 API 密钥。

编排器和直接模式有什么区别？#

作为编排器，Gitoodo 会把计划拆分成议题，为每个就绪的议题启动一个编程智能体，并合并结果；后台服务负责维护标签和工作队列。每个开启了自动驾驶的仓库都会自行处理它的议题；你可以在它的视图中看到各个会话，需要时再介入。在直接模式下只保留问我的：列出等你处理的事项（问题、议题、拉取请求、状态标签），工作由你自己启动。两种模式读取的是同样的议题；可随时在“设置 → 模式”中切换。参见入门。

为什么 Mac App Store 版本没有编排器？#

商店的沙盒不允许后台服务和工作进程。编排器随直接下载的版本提供；商店版提供带有问我的的直接模式。

我的令牌保存在哪里？#

只保存在系统的密钥存储中：macOS 钥匙串、Windows 凭据管理器或 Secret Service。无界面的服务从 systemd 凭据或服务环境中读取。令牌绝不会写入设置文件、日志、错误信息或应用界面。令牌需要哪些权限以及原因，见代码托管平台令牌。

Gitoodo 会连接哪些服务器？#

你配置的代码托管平台服务器、可选聊天通知的 Webhook、仅在你点击发送时才使用的反馈中转，以及匿名使用统计（除非你将其关闭）。包含发送内容的完整列表见网络清单。

可以关闭使用统计吗？#

可以。引导的最后一步会显示开关和所发送的内容，之后也可随时在“设置 → 通用”中关闭。完成引导之前不会发送任何内容，统计中也绝不包含仓库名或账户名、内容、令牌或服务器地址。

每个议题都要我自己写吗？#

不用，有两种方式。你可以自己写议题，在代码托管平台上写，或在仓库视图中用新任务。也可以让它们自动生成：在对话标签页描述你的目标，编排器会起草议题，每个议题是一张带有标题、正文和标签的卡片；只有当你点击应用时才会创建议题。Gitoodo 对两者一视同仁：对话使用你已连接的账户来写入，所以无论哪种方式，这个议题都属于你，描述完整后会自动变为就绪，由工作进程接手。参见对话。工作进程发现自己议题之外的工作时，也可以提议一个后续议题。Gitoodo 会创建它，并附上指向原议题的链接；它会像你自己的议题一样直接进入队列。如果你想先看每个提议，可在仓库设置的“工作者”下开启每个后续事项在处理前都需批准；之后它会在问我的中等你批准。

智能体怎样向我提问？#

需要你做决定的工作进程会在它的议题中写入一个问题块，采用公开的问题格式。Gitoodo 会在问我的中把它显示为一张回答卡片，并预先选中推荐项；发送后会发表一条简短评论，例如 1b 2 yes。你随时可以改为在代码托管平台上用普通评论回答。起初列表只显示开启了自动驾驶的仓库中等待的事项，按仓库分组，问题排在任务之前；其余内容收在末尾的提示“另有 N 项来自未开启自动驾驶的仓库 – 显示”之后，并且不计入任何数字。要查看并统计全部内容，请在“设置 → 通知”中开启“也包括未开启自动驾驶的仓库”。参见问题。

我需要 gitoodo-questions 技能吗？#

不需要，它是可选的。它教会编程智能体用 Gitoodo 的格式提问。没有它，手写的问题会显示为纯文本，并带有一个自由评论框。对于 Claude Code，请在“设置 → 技能”中安装；对于 Codex 和其他智能体，请把 skill/agents-section.md 中的这一节复制到你仓库的 AGENTS.md 中。

Gitoodo 如何合并拉取请求？#

调度器会在拉取请求完成且检查通过后合并它，合并方式由你在“设置 → 调度器”中选择（默认为 squash），可全局设置，也可按仓库设置。如果仓库不允许该方式，则按 squash、仅快进、合并提交、rebase 的顺序取第一个允许的方式。保留和否决标签可以拦住单个拉取请求；参见合并与发布和调度器参考。

工作进程可以在其他机器上运行吗？#

可以。其他主机通过 SSH 运行工作进程：gitoodo host add <name> <ssh-target> 会注册一台主机，该主机的 PATH 中需要有 gitoodo。参见卫星机器。

如何更新或卸载 Gitoodo？#

在 macOS 上，Gitoodo 会自动更新：有新版本时，应用会下载它，像安装命令一样检查 SHA-256、Developer ID 签名和公证，并在窗口关闭后重新启动。首次启动时会有提示说明；你可以随时在“设置 → 关于 Gitoodo”（“自动更新”）中关闭，那里也有“立即更新”。校验和或签名不符的软件包会被丢弃，不做任何更改。再次运行安装命令仍可原地更新。卸载命令会删除应用、命令、服务、设置、缓存、日志、已保存的令牌和技能；参见入门。

在哪里报告错误或提出功能需求？#

使用“帮助”菜单中的发送反馈，或“设置 → 关于 Gitoodo”中的反馈；只有在你点击发送时才会发出。代码改动请以拉取请求的形式提交到 dev。
