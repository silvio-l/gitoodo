分类器、调度器和 Worker

在编排器模式下，专门的服务在后台工作。即使关闭应用，它们也会继续运行。

分类器
读取 Issue 和拉取请求，设置就绪状态和依赖关系，识别你的回答并规划版本发布。
调度器
把就绪的 Issue 分派给 Worker，关注限额和卡住的会话，并合并检查通过的拉取请求。
Worker
每个 Issue 一个编程智能体，在自己的工作副本中运行。它交付一个拉取请求后结束。
分诊
用最小的模型评估每个新 Issue：类型、优先级、规模和依赖。缺少信息时会提问。“关闭”表示没有任何 Repo 开启它。

关闭窗口不会停止它们。当你在它们运行时退出 Gitoodo，它会询问该怎么做：保持服务运行（议题继续被分派和合并，问题仍会到达）或一并停止服务（应用、调度器和分类器保持关闭，直到你再次启动 Gitoodo；登录系统也不会启动它们）。不再询问会记住你的选择；之后可以在“设置 › 通用 › 退出时”中改为询问、保持服务运行或一并停止服务。菜单栏或通知区域中的 Gitoodo 菜单也提供停止服务，状态总览会显示每个服务的状态。

钥匙串和令牌#

你的代码托管平台令牌只保存在系统钥匙串中，从不写入文件。应用及其后台服务读取它们时不会询问，更新后也一样。仅当 macOS 仍然询问时（例如在 App Store 版与直接下载版之间切换后）：选择允许访问，然后选“始终允许”。

在设置的编排中设置这些服务。如果某个服务没有响应，服务状态会显示出来。
