所有仓库

本页内容
  1. 进行中
  2. 议题
  3. 拉取请求
  4. 发布
  5. 会话

所有仓库集中在一处：每个未关闭的议题及其状态、评分和正在处理它的智能体，分布在各个子页面中。搜索和筛选可按仓库、状态或标签缩小范围。

  • 智能体会话在终端中显示智能体正在运行的会话。
  • 在聊天中讨论把议题交给对话。

所有仓库把你所有的仓库集中在一处，并分成若干子页面。在编排器模式下是会话、议题和发布；在直接模式下是进行中、议题和拉取请求。带统计数据的概览不属于其中：它是首页，应用启动时显示它；点击导航的第一项概览或左上角的 Gitoodo 标志即可回到它。Gitoodo 会记住你上次使用的子页面，并再次打开它，重启之后也一样。如果你是在某个仓库的视图中关闭窗口的，应用会再次在那里打开。在所有仓库的任何位置点击议题，都会打开它的详情：仓库、状态、标签、优先级、依赖项、里程碑、谁在处理它，以及它如果属于下一个发布，原因是什么。

进行中#

需要你处理的事项和最新进展

仅限直接模式：页面显示需要你处理的事项：问我的中有多少问题在等待，计数器问题待答、已阻塞、CI 失败和停滞（点击会筛选议题下的列表），最近的处理量，以及指向未关闭拉取请求的链接。

议题#

按状态查看议题和拉取请求

列表上方的快速筛选一键显示重点：已暂停的合并、失败的检查、已阻塞、停滞和接下来。每个都显示数量，只有找到内容时才出现；再点一次即取消。

全部停止会停止一切：不开始新工作，也不合并。正在运行的智能体会把议题交还到队列中。

议题列出你已开启的仓库中的每个议题和拉取请求。在编排器模式下，它们按仓库分组：搜索所有仓库可按文字查找条目，筛选可按仓库、状态或标签缩小列表，清除筛选则再次显示全部。窗口较大时，列表与所选条目的详情并排显示。

列表上方的快速筛选一键显示以前有单独页面的内容：已暂停的合并（你暂停或否决的每个拉取请求，旁边带有放行）、失败的检查、已阻塞、停滞和接下来。每个都显示数量，只有找到内容时才出现；它保留所选仓库和搜索，再点一次即取消。

在编排器模式下，每一行都带有与其状态相符的操作：运行中的工作进程有终端；用暂停（或继续）、重启或取消来控制工作进程（取消和重启会先确认）；用优先把一个就绪的议题移到队列最前面；用控制合并来保留或否决处于评审中的议题的拉取请求。在直接模式下，分组方式可在状态、仓库、账户、数字（计数表；点击数字会打开筛选后的列表）和需要你之间切换。

拉取请求#

未关闭的拉取请求及其检查和合并状态

仅限直接模式：你所有仓库中每一个未关闭的拉取请求，按仓库分组。每个拉取请求都会显示它的检查是已通过、失败（并给出第一个失败检查的名称）、正在运行还是缺失，它是可以合并还是有冲突，以及它会关闭哪些议题。需要查看的拉取请求会突出显示，进行中会统计它们的数量。点击会在代码托管平台上打开该拉取请求。

发布#

发布是每个仓库的一个目标：发布前必须完成哪些议题。Gitoodo 会优先处理发布议题。

发布是每个仓库的一个目标：发布前必须完成哪些议题。在议题列表或发布规划中添加议题（标签 release:next）；依赖项和未关闭的 priority:p0 议题自动属于发布。代码托管平台的里程碑为它命名。

各仓库的发布进度显示每个仓库的下一个发布进行到哪一步，以及其中还有什么未完成。复制摘要会把发布计划复制为文本；选择附上 Gitoodo 链接后，末尾会附上一条指向 Gitoodo 的链接。

会话#

所有仓库中正在运行的会话实时显示，旁边是队列

每个磁贴都以缩小、实时的方式显示一个工作进程的终端。放大后终端会跟随新的输出；向上滚动时它会停住，“跳到最新”可返回底部。点击终端即可直接输入：所有按键（包括 Esc、Tab 和 Ctrl-C）都发送给代理，不会发到代码托管平台。复制：macOS 用 ⌘C；Windows、Linux 在选中文本时用 Ctrl-C，或用 Ctrl-Shift-C。点击终端外部或按 Shift-Esc 离开终端。显示的内容会经过与日志相同的脱敏处理，已知的令牌绝不会出现。

工作进程是 Gitoodo 为某个议题启动、此刻正在运行的 AI 编码会话。只有这样的会话才计入这里和标签页上的数字。仅有“进行中”标签并不代表有人在做。“活动”列出工作进程和调度器在代码托管平台上写下的内容。

议题标记为“进行中”却没有工作进程在运行时，就是无人处理，例如调度器被停止或仓库在工作进程运行时被暂停。若工作进程在已知的另一台机器上运行，会注明该机器。调度器每分钟检查一次，并会自行将无人处理达五分钟的议题改回“就绪”，你无需做任何事。“重置”可立即完成。确实有工作进程在运行的议题不会被改动。

会话以实时磁贴显示每个仓库正在运行的会话，数量越多磁贴越小；点击一个磁贴会将其放大到整个宽度。旁边是队列：每个仓库中就绪的议题，按自动驾驶处理的顺序排列，每个都附上其仓库和编号。仓库视图则为单个仓库显示同样的内容。

在放大的磁贴中，终端会填满视图，只有它会滚动。它跟随新的输出；向上滚动时它会停住，跳到最新可返回底部。点击终端即可直接在智能体的输入行中输入：所有按键（包括 Esc、Tab 和 Ctrl-C）都发送给智能体，不会发到代码托管平台。复制：macOS 用 ⌘C（在那里 Ctrl-C 发送给智能体）；Windows 和 Linux 在选中文本时用 Ctrl-C，或用 Ctrl-Shift-C。点击终端外部或按 Shift-Esc 离开终端；在终端之外，Esc 返回所有会话。终端中有未完成的输入时，Gitoodo 的指令会等待：请发送或删除那段输入。

会话（即工作进程）是 Gitoodo 为某个议题启动、此刻正在运行的 AI 编程会话，运行在这台设备上，或运行在该行中注明名称的工作机上。只有工作进程计入本页和标签页上的数字。在其他机器上列出另一台有名称的机器以仍然有效的预留所持有的议题。概览中的工作槽位磁贴统计的是同样的工作进程。这里的行操作与议题下相同：终端会打开实时终端（macOS 和 Linux），断开会离开终端而工作进程继续运行；暂停会温和地停下智能体：它完成手头的步骤然后等待，磁贴显示“已暂停”，期间 Gitoodo 不会把它当作卡住而重启；继续让它接着做。重启会在同一个 worktree 中为同一个议题换上一个全新的智能体，取消会结束会话并把议题放回队列。仓库视图中放大的磁贴带有同样的按钮。

无人处理是指仍带有“进行中”但没有工作进程在处理的议题，例如调度器在工作进程运行时被停止了。每一行都会说明原因：没有预留、预留已过期、工作进程已结束（本机的调度器曾接手过它）或预留未注明已知机器。无人处理的议题不占用工作进程名额，也不阻挡任何事情，但它们不会自行回到队列。调度器在下次启动时会释放它自己已结束的工作进程的议题。其余的可以逐个挑选，按仓库或一次性全选，并在确认后将其重置为“就绪”。Gitoodo 会为此重新读取每个议题，如果确实有工作进程在处理，就不会改动它。
