Run several coding agents in parallel

On this page
  1. One issue, one worktree, one worker
  2. How many at once
  3. More machines over SSH
  4. Cleanup
  5. Get started

Gitoodo runs several coding agents at once, up to the limit you set and your machines can carry, each on its own issue in its own worktree. This page explains how the work is split, how you set the limits, how other computers join in over SSH, and how Gitoodo cleans up after itself.

One issue, one worktree, one worker#

  • For every ready issue the dispatcher starts one worker in its own git worktree and branch, such as gitoodo/42-login-fix. Workers never share a working tree.
  • Before a worker starts, the issue is claimed with a lease and labelled in-progress. Two workers never work on the same issue, not even on two machines.
  • A worker that hangs is restarted in the same worktree; a restart after a question or a failed check also continues on the same branch.
  • Running workers survive an update or a restart of the app and its services.

How many at once#

  • In total: two workers by default, so a first setup does not start work in many repositories at once. You raise the limit in the dispatcher settings.
  • Per machine: each machine runs one worker per two processor cores by default. Under Worker machines you can set a smaller number for a weaker computer in the Workers at once field.
  • Fair across repositories: every repository with ready work gets its share of the slots, in turns. A slot no repository can use goes to one with more ready work, so no slot stays idle. An issue with priority:p0 goes first.
  • Usage limits: for Claude Code and Codex, no new worker starts once 90 % of a usage window is used (adjustable). A Claude Code session that hits its limit waits for the reset and then continues.

The overview of All repos shows how many worker slots are busy and how many issues are queued.

More machines over SSH#

Another computer can run workers for you. Add it under Settings → Worker machines with its SSH address. Gitoodo copies its command line program there over SSH, checks it against its SHA-256 checksum, and can set up the coding agents. No port is opened, and your forge token stays on your computer: the other machine clones and fetches with its own git access to the forge and sends the finished branch back, and your computer pushes it and opens the pull request. A machine that is offline gets no new work; its running issues are released after a grace period and go to the other machines. Details in Satellites.

Cleanup#

  • After every merge and every five minutes, Gitoodo removes the worktrees and local branches of merged or closed issues.
  • In your own checkouts it only removes its own worktrees and gitoodo/… branches. Your branches, stashes, the index and your uncommitted changes are never touched.
  • Work that would be lost, such as uncommitted files, is never removed silently. Gitoodo saves it as a backup branch after an hour, or lists it under Leftovers for you to decide.
  • Remote gitoodo/… branches without an open pull request are deleted after 24 hours.

Everything about the cleanup is in Repo hygiene.

Get started#

Download Gitoodo and follow Getting started; the first worker runs on your own computer, more machines can join later.
