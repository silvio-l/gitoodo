Open-Source-Orchestrator für KI-Coding-Agenten

Coding-Agenten arbeiten deine Issues ab.

Für jedes bereite Issue startet Gitoodo einen Agenten mit dem Abo, das du schon bezahlst, und mergt nach den Pflicht-Checks. Fehlt eine Entscheidung, fragt dich der Agent per Karte.

Vom Issue zum Merge, ohne dass du dazwischen musst.

Gitoodo liest deine Forge, gibt bereite Issues an Coding-Agenten auf diesem oder weiteren Rechnern und mergt, sobald die Checks durch sind, die dein Repo verlangt. Du gibst Ziel und Architektur vor, entscheidest bei Rückfragen und behältst jederzeit die volle Kontrolle.

Du programmierst nicht mehr jede Zeile – du steuerst: Richtung, Architektur, Abnahme.

  • Jede Änderung kommt als Pull Request und wird erst nach den Checks gemergt, die dein Repo verlangt, in deinem Merge-Stil. Verlangt es Reviews, wartet Gitoodo auf sie.
  • Agenten fragen im Issue nach, statt zu raten; die Frage wartet auf dich.
  • Alles oder einzelne Repos jederzeit pausieren, jeden Pull Request anhalten oder per Veto stoppen.

Ein Vorhaben auf dem Weg zum Release

  1. Vorhaben

    Du beschreibst im Chat, was entstehen soll.

  2. Issues

    Daraus werden Issues mit Abhängigkeiten und Prioritäten.

  3. Bereit

    #41 war blockiert durch #38. Nach dessen Merge ist es bereit.

  4. Agent

    Ein Agent arbeitet im eigenen Worktree und öffnet den Pull Request.

  5. Merge

    Gemergt im Stil deines Repos, Worktree und Branch sind weg.

Nächstes Release

Vom Gespräch im Chat zum gemergten Pull Request.

Gitoodo hat kein eigenes Board und keine eigene Datenbank. Was zu tun ist, steht in deinen Issues, und dort landet auch jedes Ergebnis.

Im Chat besprichst du, was entstehen soll.

Der Orchestrator-Chat ist eine Sitzung des Coding-Agenten, den du in den Einstellungen gewählt hast, mit den Werkzeugen von Gitoodo. Schlägt er Issues, Labels oder Kommentare vor, zeigt er eine Karte. Geschrieben wird erst nach „Übernehmen“.

Mit / rufst du Befehle wie /status oder /pause auf, mit # Issues und Pull Requests, mit @ Repos und Dateien. Hakt etwas, prüft /doctor Konten, Dienste und Agenten in einer Liste.

Ein größeres Vorhaben zerlegst du gemeinsam mit ihm: Jedes neue Issue schlägt er als eigene Karte vor, mit Titel, Text und Labels.

Was als Nächstes dran ist, steht schon in deinen Issues.

Gitoodo liest Labels, Abhängigkeiten und Prioritäten und berechnet daraus, welches Issue bereit ist. Zyklen in den Abhängigkeiten meldet es. Startet Gitoodo neu, liest es den Stand wieder aus der Forge.

Die Status-Labels ready, in-progress, in-review und blocked pflegt es selbst. Je Repo zeigt ein Balken, wie viel vom nächsten Release erledigt ist.

Für jedes bereite Issue ein Agent, bis zum Merge.

Du greifst nur ein, wenn ein Agent fragt, ein Merge-Konflikt einen Menschen braucht oder Checks immer wieder scheitern. Scheitert ein Issue, laufen die anderen weiter.

  1. Ein Agent startet im eigenen Worktree. Zwei Agenten nehmen nie dasselbe Issue.
  2. Hängt ein Agent, startet Gitoodo ihn neu.
  3. Der Pull Request wird aktualisiert und im Stil gemergt, den dein Repo erlaubt: Squash, Merge, Rebase oder Fast-Forward.
  4. Danach räumt Gitoodo Worktree und Branch auf.

Du kannst jeden Worker parken, neu starten oder stoppen, ein Issue nach vorn ziehen und ein Repo pausieren. Bei jedem Worker schaltest du dich ins laufende Terminal.

Für Claude Code und Codex zeigt die Statusleiste, wie viel vom Kontingent deines Abos verbraucht ist. Ab 90 % (einstellbar) startet Gitoodo mit diesem Agenten keine neuen Worker.

Mit ⌘⇧A öffnest du eine eigene Agenten-Sitzung im System-Terminal, in der Arbeitskopie oder in einem frischen Worktree.

Braucht der Agent eine Entscheidung, fragt er dich.

Der Agent fragt mit gitoodo ask oder dem Skill. Die Frage steht als Kommentar am Issue und bei dir als Karte in Gitoodo, seine Empfehlung ist schon ausgewählt. Du antwortest mit einem Klick oder tippst 1b 2 ja.

Der Zähler im Tray zeigt, wie viele Fragen warten. Mit „Mit KI besprechen“ entwirft Gitoodo eine Antwort, die erst nach deinem OK ans Issue geht.

Was im Alltag hilft

Hilfe in der App, ein Rückblick pro Woche und die Einstellungen, für die man sonst ein eigenes Skript schreibt.

  • Hilfe-Center und Tour

    Durchsuchbare Hilfe im ?-Menü und eine kurze Tour durch Tabs, Seitenleiste und Status. Du kannst sie jederzeit neu starten.

  • Wochenrückblick

    Einmal pro Woche zeigt eine Karte die letzten sieben Tage: beantwortete Fragen, mittlere Antwortzeit, gemergte Pull Requests und geschlossene Issues.

  • Fragen weitergeben

    Eine Frage an dich gibst du an eine vertraute Person weiter, das Issue wird ihr zugewiesen. Regeln je Repo schicken Fragen nach Label an die richtige Person.

  • Merge-Stil nach deiner Wahl

    Squash, Merge, Rebase oder Fast-Forward, für alle Repos oder je Repo. Gitoodo hält den Branch vor dem Merge aktuell.

  • Repos einrichten ohne Skript

    Der Einrichtungsassistent prüft mehrere Repos auf einmal, legt fehlende Labels an und zeigt, welche Repo-Einstellungen noch fehlen. Alte Labels überträgt er erst nach einer Vorschau.

  • Mehrere Konten, Tokens im Schlüsselbund

    Mehrere Konten je Forge, auch selbst gehostet. Der Token-Assistent nennt genau die Rechte, die der Modus braucht. Fragt das System nach einer Freigabe, zeigt Gitoodo „Zugriff erlauben“.

  • Startklar in einem Fenster

    Das Onboarding verbindet das Konto, wählt die Repos und richtet den Orchestrator für alle mit einem Klick ein. Vorher prüft es, ob der Agent angemeldet ist.

  • /doctor statt Rätselraten

    Eine Checkliste für Konten, Sync, Forge-Zugriff, Dienste, CLI-Versionen, Worker-Login und Skill. Jede Zeile nennt ihre Lösung.

  • Beiträge von Fremden im Stapel

    Issues von Fremden sammelt Gitoodo zur Freigabe, je Eintrag Ja oder Nein. Issues vertrauter Autoren gelten direkt als bereit.

  • Der zweite Rechner arbeitet mit

    Worker laufen auch per SSH auf weiteren Macs oder PCs. Den Host-Key prüft Gitoodo, die Forge-Tokens bleiben auf dem Hauptrechner.

  • Arbeit, die von selbst anfängt

    Automationen starten einen Prompt nach Zeitplan oder bei einem Ereignis. Dazu kommen sieben eingebaute Regeln je Repo, jede einzeln abschaltbar.

  • Mitteilungen im Team-Chat

    Slack, Teams oder Matrix per Webhook. Wer gefragt ist, wird dort erwähnt, auf Wunsch kommt einmal am Tag eine Zusammenfassung.

Häufige Fragen

Was kostet Gitoodo?

Gitoodo selbst nichts: Es steht unter der MIT-Lizenz, und Unterstützung ist freiwillig und schaltet nichts frei. Die Worker laufen über das Abo deines Coding-Agenten, das du ohnehin bezahlst.

Welches Abo brauche ich, und brauche ich einen API-Key?

Jedes Abo, mit dem die Kommandozeile deines Agenten bei dir schon läuft; einen bestimmten Tarif setzt Gitoodo nicht voraus. Einen API-Key brauchst du nicht: Gitoodo startet die Kommandozeile mit deiner Anmeldung, und die Worker sehen nie einen API-Key. Ob der Agent installiert und angemeldet ist, prüft das Onboarding vorher.

Wie viel vom Kontingent meines Agenten verbrauchen die Worker?

So viel wie jede Sitzung, die du selbst startest, denn sie laufen über dasselbe Abo. Ab Werk arbeiten höchstens zwei Worker gleichzeitig. Bei Claude Code und Codex startet Gitoodo ab 90 % des Kontingents keine neuen Worker mehr, laufende arbeiten weiter. Beides stellst du in den Einstellungen ein.

Welche Coding-Agenten kann ich nutzen?

Claude Code, Codex und Gemini CLI, im Chat wie bei den Workern. In den Einstellungen wählst du für jeden Schritt den Agenten und das Modell.

Ist automatisches Mergen sicher? Wer prüft den Code?

Gitoodo mergt erst, wenn die Checks durch sind, die dein Repo verlangt. Ein Repo ganz ohne CI wird ab Werk nach drei Minuten Wartezeit gemergt, richte deshalb zuerst CI ein. Verlangt dein Branch-Schutz Reviews, wartet Gitoodo auf sie. Jeden Pull Request kannst du anhalten oder per Einspruch sperren und ein Repo oder alles pausieren. Issues von Leuten, denen du nicht vertraust, starten erst nach deiner Freigabe einen Worker. Bei einem Merge-Konflikt bekommt das Issue needs-human und landet bei dir; die anderen laufen weiter.

Was darf ein Worker auf meinem Rechner?

Ab Werk arbeitet ein Worker ohne Rückfragen nach Berechtigungen, denn niemand sitzt davor, um sie zu beantworten; dafür erreicht ihn nur Text von Leuten, denen du vertraust. Für Repos, bei denen mehr auf dem Spiel steht, etwa öffentliche, schaltest du „Worker mit Rechteprüfung“ ein: Dann gelten die Rechteprüfung und die Sandbox des Agenten selbst.

Funktioniert das mit einem Agenten, den ich selbst starte?

Ja. Kopiere die Anleitung aus dem Skill in die Anweisungsdatei deines Repos, etwa AGENTS.md. Dann fragt auch dieser Agent im Fragenformat, und Gitoodo zeigt seine Frage als Karte. Skill und Fragenformat sind unten auf der Seite verlinkt.

Muss ich jedes Issue selbst schreiben?

Nein. Schreib Issues selbst in deiner Forge oder in der Ansicht eines Repositorys, oder beschreib im Chat, was du bauen willst: Er schlägt jedes Issue als eigene Karte vor und legt es an, sobald du „Übernehmen“ klickst. So oder so nimmt ein Agent das Issue auf, sobald es bereit ist. Auch Agenten können Folge-Issues für Arbeit vorschlagen, die ihnen unterwegs auffällt; die kommen ebenfalls in die Warteschlange oder warten auf deine Freigabe, wenn du das für das Repo einschaltest.

Läuft etwas in einer Cloud?

Nein. Die Agenten laufen auf deinen Rechnern, der Stand liegt in deiner Forge. Ein Gitoodo-Konto brauchst du nicht, deine Tokens bleiben im Schlüsselbund des Systems, und die App sendet eine anonyme Nutzungsstatistik an unseren eigenen Server in der EU: an ab Werk, ohne Cookies, nie mit Repo-Namen, Inhalten oder Tokens, und jederzeit abschaltbar.

Was passiert mit meiner Arbeit, wenn es Gitoodo nicht mehr gibt?

Sie bleibt, wo sie ist. Issues, Labels, Pull Requests und Code liegen in deiner Forge und deinen Git-Repos, nicht in Gitoodo; die App liest ihren Stand bei jedem Start von dort. Der Quellcode steht unter der MIT-Lizenz, und ein Konto, das gekündigt werden könnte, gibt es nicht.

Welche Forges werden unterstützt?

Forgejo, Gitea, GitHub und GitLab, auch selbst gehostet und mit mehreren Konten.

Auf welchen Systemen läuft Gitoodo?

Auf macOS mit Apple Silicon und auf Windows 10/11. Intel-Macs werden nicht unterstützt, und für Linux gibt es noch keine App. Die App gibt es in sechs Sprachen, Arabisch von rechts nach links, hell und dunkel, und sie lässt sich ganz mit der Tastatur bedienen.

Kann ich zeigen, dass ein Repo mit Gitoodo orchestriert wird?

Ja, mit einem statischen Badge, das nichts von Dritten lädt. Füge dieses Markdown in deine README ein: [![Orchestrated with Gitoodo](https://gitoodo.com/badge/orchestrated-with-gitoodo.svg)](https://gitoodo.com/)

Gibt es Gitoodo im App Store oder Microsoft Store?

Noch nicht. Eine Store-Version ist vorbereitet, kann wegen der Store-Sandbox aber nur Fragen beantworten und zeigen, was auf dich wartet: Agenten starten und mergen geht nur mit dem Download von dieser Seite.
