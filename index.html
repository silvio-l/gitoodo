Open-source orchestrator for AI coding agents

Coding agents work through your issues, all the way to the merge.

Gitoodo starts your coding agents on ready issues and merges once the checks your repo requires pass. You use the sign-in you already have and answer follow-up questions as cards in the app.

From issue to merge. You step in only when you are needed.

Gitoodo reads your forge, hands ready issues to coding agents on this machine or others, and merges once the checks your repository requires pass. You set the goals and the architecture, decide when an agent asks, and can stop it at any time.

You no longer write every line; you steer: direction, architecture, sign-off.

  • Every change arrives as a pull request and merges only after the checks your repository requires, in your merge style. If reviews are required, Gitoodo waits for them; change requests from trusted reviewers go back to the worker.
  • Agents ask on the issue instead of guessing; the question waits for you.
  • Pause everything or one repository at any time, hold or veto any pull request.

A project on its way to release

  1. Project

    You describe in the chat what you want to build, or let the AI interview you about it.

  2. Issues

    It becomes issues with dependencies and priorities, planned into the next release.

  3. Triage

    The smallest model sets type, priority and size where nobody has yet.

  4. Ready

    #41 was blocked by #38. Once that is merged, it is ready.

  5. Agent

    An agent works on the issue in its own working copy (a worktree) and opens the pull request.

  6. Merge

    Merged in your repo's style, worktree and branch are gone.

Next release

Your issues set the work. You decide when questions come up.

Gitoodo keeps no ticket system of its own. What needs doing is in your issues, and that is where every result ends up too: as a pull request, a comment or a label.

In the chat you talk through what you want to build.

In the chat, the coding agent you picked proposes issues, labels and comments as cards. Gitoodo writes a change to the forge only when you click “Apply”.

Type / for commands such as /status or /pause, # for issues and pull requests, @ for repos and files. If something is off, /doctor checks accounts, services and agents in one list.

You break a larger project down together: it proposes every new issue as its own card, with title, text and labels. If an idea is still vague, the interview in the new-task dialog asks you a few rounds of questions and writes the description from your answers.

What comes next is already in your issues.

Gitoodo reads labels, dependencies and priorities and works out which issue is ready. It reports cycles in the dependencies. When Gitoodo restarts, it reads the state from the forge again.

If you plan releases, Gitoodo takes on the issues of the next release first, along with their dependencies. Your releases stay milestones on your forge. When you close one, you review the plan; after your OK, Gitoodo writes the release notes, sets the tag and creates a draft release.

It maintains the status labels ready, in-progress, in-review, blocked, needs-human and stalled itself. A bar per repo shows how much of the next release is done.

One agent per ready issue, all the way to the merge.

You only step in when an agent asks or the Resolver cannot free a stuck issue. If one issue fails, the others keep going.

  1. An agent starts in its own worktree. Two agents never take the same issue.
  2. If an agent hangs or the checks fail, Gitoodo restarts it on the same branch.
  3. If an issue is still stuck after the restarts, or there is a merge conflict, the Resolver makes one attempt to fix the cause.
  4. The pull request is updated and merged in the style your repo allows: squash, merge, rebase or fast-forward.
  5. Then Gitoodo removes the worktree and the branch.

You can pause, restart or cancel any worker, boost an issue and pause a repo; ⌘⇧H stops everything. For every worker you can attach to the running terminal.

For Claude Code, Codex and Gemini CLI signed in with Google, Gitoodo shows how much of your subscription's quota is used. From 90 % (adjustable), it starts no new workers with that agent. If one of these agents runs on an API key, you set a monthly budget and see the estimated cost against it; stopping is then up to you.

⌘⇧A opens an agent session of your own inside the app, in the working copy or in a fresh worktree, or a terminal without an agent.

When the agent needs a decision, it asks you.

Questions appear as a card in Gitoodo and as a comment on the issue. The agent's recommendation is preselected; you answer with one click on the card or right on the issue.

The tray counter shows what waits for you: questions, approvals and stuck issues. With “Discuss with AI”, Gitoodo drafts an answer that only goes to the issue after your OK.

What helps day to day

Setting up repos, handing questions on, letting more machines join in: things that would otherwise be manual work or a script of your own.

  • The agent of your choice, local too

    Pick an agent and a model each for the chat, triage and workers. OpenCode and Pi also run local models, and ACP brings in more agents.

  • Questions to the right person

    Hand a question to someone you trust, or let rules per repo send it straight there by label. Over Slack, Teams or Matrix, whoever is asked gets mentioned.

  • Your merge style

    Squash, merge, rebase or fast-forward, for all repos or per repo. Gitoodo keeps the branch up to date before the merge.

  • Ready to go without a script

    Onboarding checks that your agent is signed in, connects the account and switches on the orchestrator for the repos you pick. The setup assistant creates missing labels, shows missing repo settings and moves old labels over only after a preview.

  • Several accounts, tokens in the keychain

    Several accounts per forge, self-hosted too. The token assistant lists exactly the scopes the mode needs. When the system asks for approval, Gitoodo shows “Allow access”.

  • One memory across all repos

    What keeps coming up, such as how you want something solved, Gitoodo remembers as a short entry and passes it on to the workers it fits. Suggestions from workers only count after your OK.

  • Outside contributions in one batch

    Gitoodo collects issues from outside contributors for approval, yes or no per item. Issues from trusted authors with a description count as ready straight away; a no closes the issue.

  • Your second machine joins in

    Workers also run over SSH on other Macs, PCs or Linux machines. Gitoodo checks the host key, and the forge tokens stay on the main machine.

  • Work that starts by itself

    Automations run a prompt on a schedule or on an event. On top come nine built-in rules per repo, each one can be switched off.

  • Review comments go to the agent

    When a trusted reviewer asks for changes on the pull request, the worker restarts on the same branch and works through every point. After three rounds, Gitoodo asks you.

  • Answer questions from your phone

    Paired once with a QR code, your phone shows “Asked of me” on the local network, answers cards and switches the autopilot per repo. End-to-end encrypted and off by default.

  • Stop everything in one move

    ⌘⇧H stops every worker, and Gitoodo writes nothing more to the forge. Resume brings back each repo as it was.

Frequently asked questions

What does Gitoodo add on top of my coding CLI?

Everything around the agent: Gitoodo starts it on ready issues, respects dependencies and releases, gives every issue its own worktree, collects questions as cards, restarts runs that hang and merges after the required checks and reviews. Issues, pull requests and results stay on your forge.

What does Gitoodo cost?

The app costs nothing: it is under the MIT licence, and everything this page describes is included. Workers run on the access to your coding agent that you already have; supporting Gitoodo is voluntary.

Which plan do I need? Do I need an API key?

No particular one: Gitoodo starts your agent's command line with the sign-in that already works for you, whether that is a subscription, an API key in the agent's own sign-in or a local model through OpenCode or Pi. Gitoodo itself never asks for an API key. Onboarding checks beforehand that the agent is installed and signed in.

How much of my agent's quota do the workers use?

As much as any session you start yourself, because they run on the same access. By default at most two workers run at once. For Claude Code, Codex and Gemini CLI signed in with Google, Gitoodo starts no new worker once 90 % of the quota is used; running ones carry on. For agents on an API key you set a monthly budget. You can change all of this in the settings.

Which coding agents can I use?

Claude Code, Codex, Gemini CLI, OpenCode, Pi and any agent that speaks ACP; local models too, through OpenCode and Pi. All of them except Pi can run the orchestrator chat. In the settings you pick the agent and the model for each step.

Is auto-merge safe? Who checks the code?

Your repository sets the merge requirements: Gitoodo waits for the required checks and reviews. Without CI, Gitoodo merges after a three-minute wait by default, so set up CI first. You can hold or veto any pull request and pause one repository or everything. Issues from people you don't trust start a worker only after your approval. If an issue gets stuck, on a merge conflict for example, the Resolver tries to free it first, otherwise it reaches you as a question; the others keep going.

What can a worker do on my machine?

By default a worker runs without permission prompts, because nobody sits there to answer them; in return, only text from people you trust reaches it. For repositories where more is at stake, public ones for example, switch on “Workers with permission checks”: then the agent's own permission checks and sandbox apply. OpenCode and Pi workers only run in repositories without permission checks.

Does it work with an agent I start myself?

Yes. Copy the instructions from the skill into your repo's instruction file, such as AGENTS.md. That agent then asks in the question format too, and Gitoodo shows its question as a card. The skill and the question format are linked at the bottom of the page.

Do I have to write every issue myself?

No. Write issues yourself on your forge or in a repository's view, or describe in the chat what you want to build: it proposes every issue as its own card and creates it once you click “Apply”. Either way, an agent picks the issue up as soon as it is ready. Agents can also propose follow-up issues for work they find along the way; those join the queue too, or wait for your approval if you switch that on for the repository.

Where do Gitoodo and my agents run?

Gitoodo starts the agents on your machines; whether the model behind them runs locally or at the provider depends on your agent's sign-in. The state lives in your forge, you need no Gitoodo account, and your tokens stay in the system keychain. The app sends anonymous usage statistics to our own server in the EU: on by default, no cookies, never with repo names, contents or tokens, and switchable off at any time.

What happens to my work if Gitoodo goes away?

It stays where it is. Issues, labels, pull requests and code live in your forge and your Git repositories, not in Gitoodo; the app reads its state from there on every start. The source code is under the MIT licence, and there is no account that could be closed.

Which forges are supported?

Forgejo, Gitea, GitHub and GitLab, self-hosted too and with several accounts.

Which systems does Gitoodo run on?

On macOS with Apple silicon and on Windows 10/11. Intel Macs are not supported. There is no Linux app yet. Linux machines can, however, join as workers over SSH or run the orchestrator headless as a server, set up from the command line; both with a self-built gitoodo. The app comes in six languages, Arabic right to left, light and dark, and can be operated entirely by keyboard.

Is Gitoodo in the App Store or Microsoft Store?

Not yet. A store version is prepared, but the store sandbox limits it to answering questions and showing what waits for you: starting agents and merging only work with the download from this page.
